# CLAIMS

What the Criticality Compass has shown, by class, on what data, and with what standing. One table; every evidence cell names a stored result and its sha256, and `tests/test_claims.py` checks that each one resolves.

Status words: **blind** = predictions stamped before the data were read, scored against a sealed truth. **development** = the rulebook, instrument or data was visible when it was built or read (synthetic maps included). **provisional** = scored, but on intervals or code known to be superseded; do not cite as a finding.

Evidence cells read root:path@sha256 (in code font). `cc:` is this repository; `toolset:` is the study checkout that produced the data (CC_TOOLSET, else the parent of CC_DATA_ROOT).

- **Taxonomy depth.** The release gates every unit it runs through one reader of a pinned registry projection (`registry.toml`, generated from `taxonomy/REGISTRY.toml` in the toolset at commit 5943ad3; its sha256 is pinned in `cc.toml` and printed in every report header; a mismatch makes every unit REFUSE). The projection holds 54 rows: 15 registered, 5 registered-partial, 1 registered-synthetic-only, 2 built-not-registered, 1 unbuilt, 2 non-identifiable, 3 future, 8 superseded, 17 development. The release runs 0 registered rows: none of the 15 registered rows has a release module. Its 17 units (12 instruments, 4 interval methods, the family) run as `development` rows, and every report carries the scope `development: not registered` for the units it used (the chains interval reads `release readout; equivalence to the T18 module not yet shown`). A structure whose row has no release module, or whose status is not registered, reads as a declared REFUSE (mechanism not yet available), not as absence of the phenomenon. The count is read from `registry.toml`, never typed here.
- **A positive class is not the absence of the others.** Do not read "no positive" as "nothing is critical".
